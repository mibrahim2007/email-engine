## Story

**As a developer, I want a tool-calling agent, so that replies can use knowledge and data rather than only the prompt.**

## Acceptance criteria

1. The agent exposes `search_knowledge_base`, `lookup_customer`, `call_tenant_webhook`, and `escalate_to_human`.
2. The loop is capped at 8 tool steps and 60 seconds of wall clock.
3. All model access goes through Vercel AI Gateway; no provider SDK is present in the dependency tree.
4. Tool inputs and outputs are recorded for every run.
5. Exceeding a cap ends the run cleanly with an escalation, not a partial or hung draft.

---

## AC1 lists four tools and §4.6 lists five

The architecture's agent has `propose_reply` as a **terminal** tool — it is how the draft body, citations, and confidence leave the loop. AC1 omits it, which reads as an oversight and is worth stating rather than silently building: **the terminal tool is what makes AC5 implementable.** A run that ends without calling it has produced no draft, and that is a clean, detectable outcome. A run that ends by the model simply stopping mid-sentence is not.

Build five. `propose_reply`'s payload is Story 5.3's concern; its existence and its terminal semantics are this story's.

## ⚠ AC2's 60-second cap and NFR3's 30-second budget cannot both be spent

Found comparing this story to Story 5.3 in the same epic — neither is wrong alone.

| | |
|---|---|
| AC2 here | agent loop capped at **60s** wall clock (§10.4's `AbortSignal.timeout(60_000)`) |
| Story 5.3 AC5 / NFR3 | inbound message to draft-ready under **30s at p95** |

§8.1 runs these in sequence: parse → thread resolve → **classify** (a model call) → retrieve → **agent loop** → persist. Only the agent step has a stated budget, and **it alone is permitted twice the end-to-end target.**

These are not formally contradictory — a p95 of 30s coexists with a 60s ceiling if the tail is thin. **But nothing in the epic makes that true, and nothing measures it.** NFR3 is asserted once, end-to-end, in Story 5.3 AC5; when it fails, no artifact says which step spent the time.

**Ruling: 60s is the abort, not the budget.**

- The abort stays at 60s. It exists to stop a hung run, and lowering it converts slow drafts into escalations, which is worse.
- **A soft budget of ~20s for the agent step** is what NFR3 actually implies once classify, retrieve, and persist are accounted for. Crossing it is not a failure — it is a signal, and it must be visible.
- **Per-step durations are recorded on the draft.** `drafts.tool_calls` is already `jsonb` and already carries per-step data (AC4), so this costs a field, not a table. Without it NFR3 is a number that can only be missed, never diagnosed.

## AC4 records tool calls, and one of them must be recorded differently

`search_knowledge_base` returns chunks. Recording its full output on every run means every draft carries a copy of the retrieved text — which is what Front-End Spec §4.3 wants for the trace, and what Story 5.6 AC3 shows in the playground.

**Record chunk ids, scores, and the excerpt actually shown — not whole chunk bodies.** Eight steps × several thousand tokens of chunk text, on every draft, in a `jsonb` column, on a table that grows with every inbound message. The trace needs to prove *what grounded the reply*; an id and the excerpt do that, and Story 4.1's soft delete is what keeps the id resolvable after a source is removed.

## AC5 and FR37 are the same requirement seen from two sides

AC5 is about the loop ending cleanly. **FR37 is about the loop never being redirected**: *"content inside an inbound email or a retrieved document shall never authorize a tool call or override the system prompt."*

Both are properties of the boundary between the model and the tools, and they belong in this story because this story builds that boundary. §13.1's controls:

- Inbound email bodies and retrieved KB text are wrapped in **delimited untrusted blocks**, and the system prompt states that tool use is never authorized by message content.
- **`call_tenant_webhook` accepts no model-supplied host.** The URL comes from the tenant's registration (FR49), and the model chooses *whether* to call and *with what arguments*, never *where*.

That last distinction is the one an implementation erodes. A tool signature taking a `url` parameter is a prompt injection away from being an exfiltration primitive, however carefully the prompt is worded. **The tool takes a registered webhook's identifier, not an address** — the same reasoning Story 4.1 applied to knowledge-source URLs, and the reason §13.1 already holds this rule.

Testing strategy §14.6 makes the adversarial corpus non-negotiable. It runs here, not only in Story 5.6's playground affordance.

## Tasks

### Task 1 — The loop (AC1, AC2)

- [ ] `streamText` per §10.4 with five tools, `stopWhen: stepCountIs(8)`, `abortSignal: AbortSignal.timeout(60_000)`.
- [ ] Model from `tenant.settings.model` against a per-plan allow-list.
- [ ] `experimental_telemetry` with the tenant id, as §10.4 shows.

### Task 2 — Tools (AC1)

- [ ] `search_knowledge_base` → Story 4.4's retriever. **Inside `withTenant()`** — a tool that reads tenant data on the system connection is the RLS bypass the whole design exists to prevent.
- [ ] `lookup_customer` → contact, history, custom fields.
- [ ] `call_tenant_webhook` → **registered identifier, never a URL argument.** Signed, timeout-bounded.
- [ ] `escalate_to_human` → latches `requires_human` (Story 5.1's rule), stops the loop, notifies via FR55.
- [ ] `propose_reply` → terminal.

### Task 3 — Gateway only (AC3)

- [ ] **A test asserting no provider SDK is in the dependency tree.** `@anthropic-ai/sdk`, `openai`, `@google/generative-ai` and friends absent from the lockfile. Tech stack §3 lists this as deliberately excluded; **a documented exclusion grows and a tested one has to be argued for** — the same reasoning as `system.ts`'s surface test.

### Task 4 — Recording (AC4)

- [ ] Per-step: tool, input summary, output summary, duration. Retrieval records ids, scores, excerpts — **not chunk bodies**.
- [ ] Per-step durations, for NFR3's diagnosis.

### Task 5 — Caps and the boundary (AC5, FR37)

- [ ] Step cap or timeout → escalate with a stated reason. Never a partial draft.
- [ ] Delimited untrusted blocks for email bodies and retrieved text.
- [ ] §14.6's adversarial corpus in CI.
