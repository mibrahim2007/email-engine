## Story

**As a user,**
**I want a consistent navigation shell,**
**so that the product feels like one application.**

## Acceptance criteria

1. `(app)` layout renders sidebar, organization switcher, user menu, and content area.
2. shadcn/ui is initialized in `packages/ui`; Tailwind v4 theme tokens are defined CSS-first with light and dark values.
3. Dark mode follows the system preference and can be toggled, persisting across sessions.
4. The shell is responsive to 768px and passes an automated accessibility scan with no critical violations.
5. Navigation items reflect the current user's role — billing is hidden from `agent` and `viewer`.

---

## ⚠ AC5 is presentation, not authorization

"Navigation items reflect the current user's role" is a **usability** requirement. Implement it and stop, and you have built security theatre: the billing page is one typed URL away.

**`requireRole()` still guards the route and every mutation behind it** (§15.8). Hiding the link means an `agent` is not shown a door they cannot open; it does not lock the door. Both are needed, and only one of them is security.

Add a test that an `agent` navigating **directly** to `/settings/billing` gets 403 — not merely that the link is absent.

## Tasks

### Task 1 — shadcn/ui in `packages/ui` (AC2)

- [ ] Initialize shadcn via its CLI into `packages/ui`, re-exported from `src/index.ts`. Story 1.1 created the package empty for exactly this.
- [ ] **The Tailwind theme already exists** — Story 1.1 wrote `packages/config/tailwind/theme.css` with the §9.2 `@theme` block and light/dark values. Extend it; do not create a second source of tokens.
- [ ] **No `tailwind.config.js`.** Tailwind v4 is CSS-first (§3, §9.2). If a shadcn generator writes one, delete it.
- [ ] Install only the primitives the shell needs — Front-End Spec §7's *Global* row: `sonner`, `dialog`, `command`, `dropdown-menu`. Inbox and draft primitives arrive with Epics 3 and 5.

### Task 2 — The shell (AC1)

- [ ] `(app)/layout.tsx`: sidebar, `<OrganizationSwitcher />` from Story 1.4, user menu, content area.
- [ ] Sidebar per Front-End Spec §2.2 — 240px, collapsible to a 56px icon rail.
- [ ] **Saved views are navigation, not filters.** "Unassigned", "Mine", "Needs human" are sidebar links carrying URL params, because Story 3.2 AC4 requires one click and a filter panel is two. The links can exist now with counts stubbed at zero.
- [ ] **"Needs human" shows `0` rather than disappearing.** A queue that vanishes when empty teaches agents to stop looking at it.
- [ ] Server Component by default; `"use client"` only on the leaves that need it, each with a comment saying why (§15.7).

### Task 3 — Dark mode (AC3)

- [ ] Follows `prefers-color-scheme`, toggleable, persisted.
- [ ] **No flash of the wrong theme on load.** Persisted preference must be applied before first paint — a blocking inline script that sets the class on `<html>`, not a `useEffect`. This is the one place a render-blocking script is correct.
- [ ] Tenant brand overrides are emitted as **inline CSS custom properties on the app shell** (§9.2), never a rebuild. Not needed until a tenant sets one, but the shell is where they would land — leave the seam.

### Task 4 — Responsive and accessible (AC4)

- [ ] Breakpoints per Front-End Spec §10: ≥1280px three columns, 1024–1279 contact panel becomes a sheet, 768–1023 sidebar becomes an icon rail, <768 single column.
- [ ] **Add axe-core to CI.** Story 1.1's CI runs typecheck, lint, test, build — no accessibility scan exists yet, so this story adds it. "Passes an automated scan" is not verifiable until something runs one.
- [ ] Radix via shadcn handles primitive keyboard and ARIA behaviour; **the obligation is on the custom composites** (Front-End Spec §11). At this story that means the sidebar and the org switcher.
- [ ] Touch targets ≥44px (Front-End Spec §3.4).

### Task 5 — Role-aware navigation (AC5)

- [ ] Nav items filter on the role from `requireTenant()`. Billing hidden from `agent` and `viewer`.
- [ ] **Plus the route guard** — see the warning above. The test is direct navigation, not link absence.

## Dev notes

### The theme is already written — [§9.2](../architecture/frontend-architecture.md)

`packages/config/tailwind/theme.css` exists from Story 1.1 with `--color-background`, `--color-foreground`, `--color-primary`, `--color-muted`, `--color-border`, `--color-destructive`, `--radius`, `--font-sans`, and a `.dark` block. Add tokens there.

### Sidebar — Front-End Spec [§2.2](../front-end-spec/information-architecture.md)

```
┌────────────────────┐
│ ◈ Acme Support  ▾  │  OrgSwitcher (Clerk)
├────────────────────┤
│ ▸ Inbox         12 │  count = open + unassigned
│   ├ Unassigned   5 │  saved views — links, not filters
│   ├ Mine         3 │
│   └ Needs human  2 │  ← always visible, shows 0 rather than hiding
│ ▸ Knowledge        │
│ ▸ Playground       │
│ ▸ Analytics        │
├────────────────────┤
│ ⚙ Settings         │
│ ⌘K                 │  palette hint, not a button
└────────────────────┘
```

Counts poll on the same 10s SWR cycle as the inbox (§9.3), not a separate request. **Stub them at zero in this story** — there are no conversations until Epic 2.

### Performance budgets this story starts spending — Front-End Spec §12

| | |
|---|---|
| Client JS | **< 200KB gzipped for the whole dashboard** (NFR6) |
| LCP p75 | < 1.8s |
| INP p75 | < 200ms |

The shell is the first real client-side code in the product. **Every shadcn primitive installed here is spent budget for every later screen**, which is why Task 1 limits the install to the Global row. Front-End Spec §12 also rejects a rich-text editor later on this basis — the ceiling is real, and it starts being consumed now.

### What is not this story

`CommandPalette` (Story 3.6), the inbox itself (Epic 3), `ConfidenceMeter` and the draft panel (Epic 5). The shell renders an empty content area; that is correct.
