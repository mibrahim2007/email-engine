## Story

**As an agent, I want to triage a conversation, so that work is distributed and tracked.**

## Acceptance criteria

1. Status can be changed to `open`, `pending`, `resolved`, or `spam` from the list and the detail view.
2. A conversation can be assigned to any member; assignment notifies the assignee.
3. Changes apply optimistically and reconcile; a failure rolls back visibly with an explanation.
4. The contact panel shows the sender's name, company, custom fields, and prior conversations.
5. Every status and assignment change writes an audit event.

---

## ⚠ AC3's rollback is the requirement, not the optimism

Optimistic UI is easy; **the honest failure is the hard half**. Front-End Spec §9 is blunt about it: *a silent revert is worse than no optimism*, because the agent believes the change landed and moves on.

- The row reverts **with a visible animation** and a toast stating what failed and why.
- Never a bare "Something went wrong" — §15.9's taxonomy classes exist so the message can be specific.
- **Test the failure path**, not just the success path. An optimistic update whose rollback has never run is a rollback that does not work.

## This story does not build `audit()` or `notify()`

Both arrive in Epic 1 — `audit()` in Story 1.5, `notify()` in Story 1.7. **This story is their second caller and must not write its own insert.** That distinction is what findings F3 and F8 turned on.

## Tasks

### Task 1 — Status and assignment (AC1, AC2)

- [ ] Server Actions guarded by `requireRole()` before touching data (§15.8) — a `viewer` gets 403.
- [ ] Assignment calls `notify()` for the assignee. In-app only; **this is not one of FR56's two email conditions**, and widening that list is how notification fatigue starts.

### Task 2 — Optimistic with a real rollback (AC3)

- [ ] `useOptimistic` for status and assignment (§9.3).
- [ ] Rollback per the section above.

### Task 3 — Contact panel (AC4)

- [ ] Name, company, custom fields, prior conversations. RLS scopes it; no `tenant_id` predicate (§15.2).
- [ ] Prior conversations are a link list, not an embedded thread — the panel is reference, and Front-End Spec §3.1 gives it the narrowest column for that reason.

### Task 4 — Audit (AC5)

- [ ] Every status and assignment change calls `audit()` **inside the same transaction as the change** (Story 1.5). A separately-committed audit row can record a change that rolled back.
