## Story

**As a developer,**
**I want Postgres provisioned with a migration workflow,**
**so that schema changes are versioned and reviewable.**

## Acceptance criteria

From [PRD Epic 1](../prd/epic-1-foundation-and-tenancy.md), including the four amendments made after the PO gate:

1. Neon Postgres provisioned via Vercel Marketplace; `DATABASE_URL` and unpooled variant set in all three environments.
2. `vector`, `pg_trgm`, and `citext` extensions enabled. *(Corrected — `pgcrypto` is obsolete, `citext` was missing.)*
3. Drizzle schema defines `tenants`, `users`, `memberships` with the fields in the architecture data models.
4. `drizzle-kit generate` produces a checked-in migration; `migrate` applies cleanly to an empty database.
5. CI fails if the committed schema and migrations have drifted.
6. A seed script creates two tenants with distinct users for local development.
7. **Point-in-time recovery** enabled with a retention window of at least 7 days, and a restore to an arbitrary point exercised once and documented (NFR20).
8. `tenants` carries `region text NOT NULL DEFAULT 'us-east' CHECK (region IN ('us-east'))` (§6.8b, §6.8d, NFR22) and `slug` is `citext`.
9. The Drizzle schema defines **intended** types, never the substitutions in `migrations/0001`. `migrations/0001`–`0003` are **never applied to Neon** (§6.8c); the live schema comes from Drizzle.

*ACs 8 and 9 as shown are the tightened wording. This draft is what caused the tightening — see below.*

## ✅ Why ACs 8 and 9 were tightened — resolved 2026-08-04

*Kept as the record. The PRD wording above already reflects this; what follows is why it changed.*

As originally written, AC3 and AC8/AC9 disagreed. **AC3 scopes this story to three tables** — `tenants`, `users`, `memberships`. But:

| Named in AC8/AC9 | Lives on | Created by |
|---|---|---|
| `tenants.region` | `tenants` | ✅ **this story** |
| `tenants.slug` as `citext` | `tenants` | ✅ **this story** |
| `attachments.scan_status` | `attachments` | Epic 2, Story 2.5 |
| `vector(1536)`, HNSW index | `kb_chunks` | Epic 4, Story 4.3 |

**Resolution — do not widen this story.** Build the three tables AC3 names, with `region` and `citext` correct. Enable all three extensions (AC2) even though nothing here uses `vector` or `pg_trgm` yet: extensions are database-level, they are free once created, and the alternative is a later story needing a migration that only turns one on.

The rest of AC8/AC9 is a **forward instruction to the stories that create those tables**, and both already carry it — Story 2.5 AC7 writes `scan_status` as `not_scanned`, and Epic 4 builds `kb_chunks` against §6.2. Record it and move on.

**Outcome:** the PRD was tightened the same day. AC8 now names only `tenants.region` and `citext`; AC9 keeps the rule that matters — Drizzle defines intended types and `migrations/0001`–`0003` never touch Neon — without naming Epic 4's tables. The lesson worth keeping: **resolving a finding by appending an acceptance criterion somewhere plausible is how scope inflates**, and drafting is where that gets caught.

## Dev notes

### The tables — from [§6.2](../architecture/database-schema.md), corrected

```sql
CREATE EXTENSION IF NOT EXISTS "vector";
CREATE EXTENSION IF NOT EXISTS "pg_trgm";
CREATE EXTENSION IF NOT EXISTS "citext";
-- NOT pgcrypto: gen_random_uuid() is core in PostgreSQL 13+.

CREATE TABLE tenants (
  id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name         text NOT NULL,
  slug         citext UNIQUE NOT NULL,
  clerk_org_id text UNIQUE NOT NULL,
  plan         text NOT NULL DEFAULT 'trial',
  status       text NOT NULL DEFAULT 'active',
  settings     jsonb NOT NULL DEFAULT '{}'::jsonb,
  region       text NOT NULL DEFAULT 'us-east'
                 CHECK (region IN ('us-east')),   -- §6.8b/§6.8d, NFR22
  created_at   timestamptz NOT NULL DEFAULT now()
);

-- Identity is owned by Clerk. `users` is a mirror and is intentionally
-- global — a user may belong to many tenants — so it carries no tenant_id
-- and gets no RLS policy. This is the one table that is meant to look wrong.
CREATE TABLE users (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  clerk_user_id text UNIQUE NOT NULL,
  email         citext NOT NULL,
  name          text,
  avatar_url    text,
  created_at    timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE memberships (
  id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id  uuid NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
  user_id    uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  role       text NOT NULL CHECK (role IN ('owner','admin','agent','viewer')),
  created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (tenant_id, user_id)
);

CREATE INDEX idx_memberships_user ON memberships (user_id);
```

> **`users` has no RLS and that is correct.** Story 1.3's coverage test walks the catalog for tables carrying `tenant_id`; `users` has none, so it is skipped by construction rather than by exception. Do not add a `tenant_id` to make it look consistent.
