## Story

**As an agent, I want to read a full thread, so that I have the context to reply.**

## Acceptance criteria

1. Messages render chronologically with sender, recipients, timestamp, and direction clearly distinct.
2. Quoted history is collapsed by default and expandable inline.
3. Sanitized HTML renders inside a sandboxed iframe with a strict CSP.
4. Attachments are listed with type icons and download via signed, expiring URLs.
5. The view is dynamic and never served from cache.
6. Server response for the conversation detail is under 300ms at p95 (NFR2).

---

## ⚠ AC3 is the *second* control, not a repeat of Story 2.5

Story 2.5 sanitised the HTML on the way in. This story renders it. **Both are required and neither is redundant**: a sanitizer bypass discovered next year is survivable behind a CSP, and a CSP misconfiguration is survivable behind a sanitizer. Defence in depth only works if each layer is built as though the other might fail.

- **Sandboxed iframe**, no `allow-same-origin` together with `allow-scripts` — that pairing re-grants everything the sandbox removed.
- **Strict CSP on the frame**, not inherited from the app.
- **Remote images stay blocked** until the agent asks (Story 2.5 AC4). They are tracking pixels by default; the affordance should say so rather than just "show images".

## ⚠ The timeline is not only messages

NFR23, Story 5.4 AC3 and Story 6.5 AC4 all require system events **in the conversation timeline** — a failed draft, an escalation reason, a delivery failure. Architecture §6.7 built `conversation_events` for exactly this.

**So the detail view renders a merged, ordered list of `messages` *and* `conversation_events`.** `MessageBubble` alone cannot express it — Front-End Spec §7 names `TimelineEvent` as a separate composite. Build the merge here even though the only producers arrive in Epics 5 and 6; retrofitting a second row type into a rendered list later is worse than leaving one unused.

## Tasks

### Task 1 — The thread (AC1, AC2)

- [ ] Chronological, with direction visually distinct. Inbound and outbound must not be told apart by colour alone (NFR24).
- [ ] Quoted history collapsed, expandable inline. Story 2.5 produced the split; this renders it.

### Task 2 — Safe rendering (AC3)

- [ ] Sandboxed iframe + strict CSP per the section above.

### Task 3 — Attachments (AC4)

- [ ] Type icons from the **true type** Story 2.5 stored, not the filename — `invoice.pdf.exe` shows as an executable.
- [ ] **Signed, expiring URLs.** A blob URL that does not expire is a permanent unauthenticated link to a customer's document.
- [ ] Surface `scan_status = not_scanned` honestly in the UI (FR57).

### Task 4 — Timeline merge (§6.7)

- [ ] **`conversation_events` in the Drizzle schema** — table, RLS policy, and `SELECT, INSERT` only, append-only like `audit_events` (§6.7). This story is the first in sequence to touch it and owns it as of 2026-08-07 (§6.7d); Stories 5.1, 5.3, 5.4, 6.3, 6.4 and 6.5 all write rows into it.
- [ ] Merge `messages` and `conversation_events` by `created_at`, rendering `TimelineEvent` for the latter.

### Task 5 — Dynamic and fast (AC5, AC6)

- [ ] Never cached (§9.4). A cached conversation shows an agent a thread that has moved on.
- [ ] < 300ms p95 against the scale fixture — **the measurement NFR2 actually names**, which Story 3.1 AC5 does not cover because that measures the list.
