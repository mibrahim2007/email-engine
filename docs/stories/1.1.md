## Story

**As a developer,**
**I want a deployable monorepo with CI,**
**so that every later story lands in a working pipeline.**

## Acceptance criteria

Verbatim from [PRD Epic 1](../prd/epic-1-foundation-and-tenancy.md):

1. Turborepo monorepo with `apps/web` and `packages/{db,email,ai,ui,config}` per the architecture's source tree.
2. Next.js App Router app builds, typechecks, and lints with zero errors.
3. `/api/health` returns `{ status, version, commit }` and is reachable on a deployed URL.
4. Pushing to a branch produces a Vercel preview deployment.
5. CI runs typecheck, lint, and unit tests on every PR and blocks merge on failure.

## 🛑 Read this before your first command

**The repository is not empty, and nothing in it may be destroyed.** It currently holds the planning artifacts, the applied database schema, and a working CI workflow:

```
email-engine/
├── Email Engine PRD.md                  ← keep
├── Email Engine Architecture.md         ← keep
├── Email Engine Front-End Spec.md       ← keep
├── README.md                            ← keep, extend
├── .gitignore                           ← keep, extend
├── .bmad-core/core-config.yaml          ← keep
├── docs/{prd,architecture,front-end-spec,stories}/   ← keep

├── tests/rls_{isolation,policy_coverage}.sql        ← keep, do not touch
└── .github/workflows/db.yml             ← keep, do NOT replace (see Task 5)

`create-turbo` and `create-next-app` both refuse to run in a non-empty directory, and forcing them will overwrite `README.md` and `.gitignore`. **Scaffold into a temp directory and copy in, or hand-write the workspace files.** Hand-writing is fine — there are six of them.

`migrations/` and `tests/` hold SQL that is applied to a live database and guarded by `db.yml`. They belong to Story 1.2/1.3 and are out of scope here. Do not move, rename, or "tidy" them.

## Tasks

### Task 1 — Workspace root (AC1)

- [ ] `package.json` at root: `"private": true`, `"packageManager": "pnpm@9"`, workspaces via `pnpm-workspace.yaml` (`apps/*`, `packages/*`).
- [ ] `turbo.json` with tasks `build`, `dev`, `lint`, `typecheck`, `test`. `build` depends on `^build`; `dev` is persistent and uncached.
- [ ] `.nvmrc` / `engines` pinning **Node 22.x**.
- [ ] Extend `.gitignore`: `node_modules/`, `.next/`, `.turbo/`, `.vercel/`, `*.tsbuildinfo`. (`.env*` and the editor/OS entries are already there.)
- [ ] Root scripts delegate to turbo: `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`.

> **pnpm is an SM assumption, not an architecture decision.** §3 pins every library version but names no package manager. pnpm is the Turborepo default and the only one whose workspace protocol makes `packages/config` painless. If the Architect prefers npm, this is a one-file change — flag it rather than silently switching.

### Task 2 — `packages/config` (AC1, AC2)

- [ ] `packages/config/tsconfig/base.json` — `strict: true`, `noUncheckedIndexedAccess: true`, `moduleResolution: "bundler"`, target ES2022.
- [ ] `packages/config/tsconfig/nextjs.json` extending base.
- [ ] `packages/config/eslint/base.js` — flat config, TypeScript, `no-explicit-any` as **error** (coding standard 11).
- [ ] `packages/config/eslint/next.js` extending base with the Next plugin.
- [ ] `packages/config/tailwind/theme.css` — the `@theme` block from §9.2, light and dark. Tailwind v4 is **CSS-first: do not create `tailwind.config.js`.**

The `no-restricted-imports` rule for `db` (coding standard 1) belongs to Story 1.2, when `packages/db` gains real contents. Leave a `// TODO(1.2)` comment where it will go.

### Task 3 — Empty packages (AC1)

- [ ] `packages/{db,email,ai,ui}` each with `package.json`, `tsconfig.json` extending the base, and `src/index.ts` exporting nothing yet.
- [ ] They must typecheck and lint clean. Subdirectories from §11 (`db/{schema,repositories,…}`) are **not** created here — later stories create them with their contents. An empty directory is not a deliverable.

### Task 4 — `apps/web` (AC2, AC3)

- [ ] Next.js 16 App Router, TypeScript, importing config from `packages/config`.
- [ ] Route groups from §9.1 as empty scaffolding: `src/app/(marketing)/page.tsx` with a placeholder landing page. **Do not create `(app)` or `(auth)`** — they need Clerk, which is Story 1.4.
- [ ] `src/app/api/health/route.ts` returning `{ status: "ok", version, commit }`:
  - `version` from `package.json`.
  - `commit` from `process.env.VERCEL_GIT_COMMIT_SHA ?? "local"`.
  - `export const dynamic = "force-dynamic"` — a cached health check reports the health of a past deploy.
- [ ] `src/server/env.ts` — zod-validated env, read at boot. **Coding standard 6: `process.env` anywhere else is a lint error.** Only `VERCEL_GIT_COMMIT_SHA` and `NODE_ENV` exist at this story; the file's job is to exist so later stories extend it.
- [ ] `src/app/layout.tsx` importing the Tailwind theme.
- [ ] One Vitest unit test for the health handler asserting shape and status 200.

### Task 5 — CI (AC5) ⚠ additive

- [ ] **New file** `.github/workflows/ci.yml`. **Do not edit or replace `db.yml`** — it runs the RLS suites and is already green; the two workflows are independent check runs on the same PR.
- [ ] Triggers: `pull_request`, and `push` to `main`.
- [ ] Steps: checkout → pnpm/Node 22 with cache → `pnpm install --frozen-lockfile` → `pnpm typecheck` → `pnpm lint` → `pnpm test`.
- [ ] No `paths` filter. `db.yml` scopes itself to `migrations/`+`tests/` because SQL changes are the only thing that can break it; application CI must run on every PR.
- [ ] AC5 says CI "blocks merge on failure". The workflow failing is necessary but not sufficient — **branch protection is a repository setting, not a file.** See Prerequisites.

### Task 6 — Vercel (AC3, AC4)

- [ ] `apps/web/vercel.json` — leave crons out; they arrive with the cron routes in Epics 2 and 6. An empty `vercel.json` is acceptable, or omit the file.
- [ ] Confirm the deployed preview serves `/api/health` with a real commit SHA.
- [ ] Record the preview URL in the Dev Agent Record.

Everything below is excerpted so you do not have to open the architecture. Source shards are named if you want more.

│   ├── src/app/                   routes (§9.1)
│   ├── src/components/            app-specific components
│   ├── src/server/                backend (§10.1)
│   ├── src/hooks/
│   ├── public/
│   ├── next.config.ts
│   └── vercel.json                crons
├── packages/
│   ├── db/{schema,repositories,migrations,seed}
│   ├── email/{parse,sanitize,thread,render}

```

> **Two deviations already in effect — do not "fix" them.** §11 shows `docs/prd.md` and `docs/architecture.md`; this repo keeps the source documents at the root under human-readable names and puts *shards* in `docs/prd/` and `docs/architecture/`. And `packages/db/migrations` is where Drizzle migrations will live in Story 1.2 — the root-level `migrations/` holds the hand-written SQL that is already applied. They coexist.

### Versions you may install — [§3](../architecture/tech-stack.md)

**This table is the single source of truth. Anything not listed needs an architecture change, not an ad-hoc `pnpm add`.** Relevant to this story:

| Category | Technology | Version |
|---|---|---|
| Language | TypeScript | 5.9 |
| Framework | Next.js | 16.x (App Router) |
| Runtime | Node.js | 22.x |
| Styling | Tailwind CSS | 4.x — CSS-first `@theme`, **no `tailwind.config.js`** |
| Testing | Vitest + Testing Library | 3.x |

Everything else in §3 — Clerk, Drizzle, the AI SDK, Stripe, Resend, Upstash — belongs to later stories. **Installing them now is scope creep and will fail review.**

### Coding standards that bite in this story — [§15](../architecture/coding-standards.md)

6. **Environment variables are read only in `server/env.ts`**, validated by zod at boot. `process.env` elsewhere is a lint error.
7. **Server Components by default.** `"use client"` requires a comment explaining what needs the client.
11. **No `any`.** `unknown` plus a narrowing parse.
12. **Naming:** components `PascalCase`, hooks `useCamelCase`, routes `kebab-case`, API fields `camelCase` in JSON.

Standards 1–5, 8–10 reference the database, email pipeline, and agent — none exist yet. They arrive with the stories that create them.

### Deployment context — [§12](../architecture/deployment.md)

| Environment | Branch | URL |
|---|---|---|
| Development | local | `localhost:3000` |
| Preview | any PR | `email-engine-{hash}.vercel.app` |
| Production | `main` | `app.emailengine.io` |

The full pipeline §12 describes — drift check, RLS test, Playwright, pre-deploy migrations, smoke test, auto-rollback — is built up across Epic 1. **This story delivers the first three steps only: typecheck, lint, unit tests.** The RLS test already runs via `db.yml`. Playwright is Story 1.6+; migrations run in a pre-deploy job from Story 1.2.

§12 lists fifteen environment variables. **None of them are needed by this story** and `env.ts` should not demand them — a schema requiring `CLERK_SECRET_KEY` will fail the build for five more stories. Add each variable in the story that first uses it.
