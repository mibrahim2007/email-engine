## Story

**As an agent, I want a fast list of conversations, so that I can see what needs attention.**

## Acceptance criteria

1. The inbox renders as a Server Component, sorted by `last_message_at` descending.
2. Each row shows sender, subject, snippet, status, assignee avatar, message count, and relative time.
3. Cursor pagination loads more without a full page reload; the list handles 50,000 conversations without degradation.
4. Empty, loading, and error states are designed, not default.
5. Server response for the first page is under 300ms at p95 against seeded production-scale data.

---

## Prerequisites

**Seeded production-scale data.** AC5 and AC3 are meaningless without it — 50,000 conversations per tenant across 500 tenants (NFR7). Story 1.2's seed script creates two tenants for development; **this story needs a separate scale fixture**, and generating it is real work rather than a dependency.

## Tasks

### Task 1 — The query (AC1, AC5)

- [ ] Server Component, `ORDER BY last_message_at DESC`. `idx_conv_tenant_status_last` already covers `(tenant_id, status, last_message_at DESC)`.
- [ ] **No `tenant_id` in the query** (§15.2). RLS scopes it; a manual filter hides a missing policy.
- [ ] AC5 is measured against the scale fixture, not a dev database with twelve rows.

### Task 2 — Pagination without a virtualiser (AC3)

- [ ] **Cursor pagination, not offset.** `OFFSET 40000` scans and discards 40,000 rows; a cursor on `(last_message_at, id)` does not.
- [ ] **No windowing library** — Front-End Spec §12 delta 5 ruled it out. 50,000 rows never reach the DOM because pagination keeps them out; the real risk is a long session accumulating appended pages.
- [ ] **Bound the retained window to ~200 rows**, dropping from the top with a spacer to hold scroll position. An array slice, zero bytes against the 200KB budget Story 1.6 now enforces.

### Task 3 — The row (AC2)

- [ ] Sender, subject, snippet, status, assignee avatar, message count, relative time.
- [ ] **Density is the feature** — Front-End Spec §6.1 targets ≥18 rows visible at 1080p without scrolling.
- [ ] `ConversationRow` stays a **Server Component**; the optimistic status change (Story 3.4) lives in a small client leaf inside it rather than promoting the whole row.
- [ ] The `✎87` draft-ready badge is Epic 5. Leave the slot; do not stub a fake confidence.

### Task 4 — States (AC4)

- [ ] **Skeletons matching the final layout**, never a centred spinner (Front-End Spec §9).
- [ ] Empty: says what it is, why, and the one action that changes it — "No conversations yet — connect a mailbox to start receiving mail."
- [ ] Error: a plain cause and a retry that retries *that thing*, not the page.
