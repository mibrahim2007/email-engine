## Story

**As an agent, I want a draft with its sources, so that I can verify it in seconds instead of re-researching.**

## Acceptance criteria

1. Drafts are generated for classified messages that do not require a human.
2. Each draft records body text and HTML, confidence, citations, model, and tool calls.
3. Every factual claim maps to a retrieved chunk; ungrounded claims lower the confidence.
4. The draft respects the tenant persona — tone, formality, prohibited topics, disclaimers.
5. Drafts appear within 30 seconds of message arrival at p95.

---

## 🔴 AC3 asks the model to grade itself, and the entire product is built on that grade

`propose_reply` emits body, citations, **and confidence** — all three generated by the same model, in the same call, from the same context. AC3's "ungrounded claims lower the confidence" is an instruction in a prompt, and its compliance is checked by nothing.

**Look at what that number carries:**

| Consumer | Uses confidence to |
|---|---|
| Front-End Spec §4.1 | Drive four redundant encodings, a band label, and **the threshold marker** — "the trust-building device" |
| Story 5.4 AC1 | Escalate below a floor |
| **Epic 6 / FR42** | **Send without human review above a tenant-set threshold** |
| PRD §8 Q1 | Choose between defaulting to 0.9 and 0.85 |

**Q1 presumes the number is calibrated.** Choosing between 0.85 and 0.9 is only a meaningful decision if a 0.87 draft is reliably worse than a 0.92 one — across tenants, across intents, across weeks, and after a model version changes underneath it. **A self-reported score has none of those properties**, and language models are known to report high confidence in exactly the situation this product most needs caught: a fluent, plausible answer to a question the knowledge base does not cover.

The failure mode is precise. Auto-send is armed at 0.9. A customer asks something the KB does not answer. The model writes a confident, well-formed, **wrong** reply, scores itself 0.94, and the product sends it without a human ever seeing it. **Every supervision surface worked**: the citation popover shows the chunks it did retrieve, the meter shows 94, the trace shows the tool calls. Nothing in the system disagrees with itself.

> ### ✅ Resolved 2026-08-07 — PRD Q10 closed as option B
> **`confidence` is computed groundedness**; the self-report is kept as `drafts.model_confidence` and gates nothing. The full ruling, including the three definitions that stop the model scoring itself, is [[Email Engine Architecture]] §10.4. AC3 is implementable as of today and this story is no longer blocked.
>
> The analysis below is kept as the record of why. **What decided it was AC4 of Story 6.3**, not the failure mode: an admin must acknowledge a plain-language explanation before arming auto-send, and under option A the honest version of that sentence was *"84 drafts the model felt good about"*.

**The three options as raised:**

| Option | What it is | Cost |
|---|---|---|
| **A — self-report (as specified)** | The model's own number | Free. **Uncalibrated, and unfalsifiable from inside the system** |
| **B — mechanical groundedness** | Fraction of the draft's factual sentences carrying a resolvable citation, computed in code | Cheap, deterministic, explainable. Measures grounding, **not correctness** |
| **C — a second-model check** | A cheap call scoring each claim against the retrieved chunks it cites | One extra fast-tier call per draft. Independent of the drafting context |

**Chosen: B, with A recorded alongside it.** Confidence is computed rather than claimed, and an agent can be told what it means in one sentence — *"84% of this reply's factual sentences are backed by a source you can click"*. That is the number Front-End Spec §4.1's meter carries, because the meter's job is to make grounding legible.

Keep the self-report as a **second recorded field**, unused by any gate. The gap between claimed and computed confidence is the most useful signal this product could collect about its own model, and it costs a column.

**C stays on the table for Epic 6**, when auto-send makes the stakes real, and its cost is best judged against Story 5.1's eval data.

**AC3's "ungrounded claims lower the confidence" now has a mechanism**, and it is the arithmetic itself: an uncited claim sentence is a miss in the numerator, so the score falls without anything needing to be instructed. **A metric that cannot be complied with selectively does not need compliance.**

## AC2's `citations` must survive their sources

`drafts.citations` is `jsonb` (§6.2). It carries no foreign key, so nothing cascades and nothing errors when a `kb_source` is deleted — **the citation popover's "link to the source" simply 404s**, on the surface built to answer *"can I trust this"*.

Raised drafting Story 4.1 and deliberately not appended to a story then. **It lands here**, where citations are written, and in Story 5.5, where they are rendered.

Story 4.1 soft-deletes sources so the row remains resolvable. This story's part: **each citation records the chunk id, the source id, the source title, and the excerpt as it was at draft time.** A citation is a record of what grounded a reply *when the reply was written* — re-resolving it later against a re-indexed source is not the same claim, and after Story 4.3's nightly re-index the chunk id may legitimately no longer exist.

Denormalising the excerpt is correct here for the same reason `audit_events` is append-only: **it is evidence, not a view.**

## AC5 is NFR3, and Story 5.2 records what it needs to be diagnosable

30s p95 end-to-end, against an agent loop permitted 60s. Story 5.2 rules the cap an abort and ~20s the working budget, and records per-step durations. **This story asserts the end-to-end number; that story makes a miss explicable.**

Measure from `messages.received_at`, not from workflow start — the queue wait is part of what the customer experiences and excluding it measures a system nobody is running.

## AC4's persona has one criterion that is not like the others

Tone, formality, and signature shape the output. **Prohibited topics constrain it**, and a constraint expressed only as prompt text is a request.

The prompt states them, and a check after generation asserts the draft does not address a prohibited topic — escalating rather than sending if it does. Story 5.6 configures the list; enforcement lives with generation, and **the same rule as Story 1.6's route guard applies: telling the model is presentation, checking the output is enforcement.**

## Tasks

### Task 1 — Draft generation (AC1, AC2)

- [ ] Runs on classified messages where `requires_human` is false — **read the latch, not the last classification** (Story 5.1).
- [ ] Persist body text, body HTML, confidence, citations, model, tool calls.
- [ ] Workflow step per §8.1, so a failure retries generation and not the retrieval.

### Task 2 — Confidence (AC3)

- [ ] `confidence = resolvable-cited claim sentences / claim sentences`, computed after generation.
- [ ] **The denominator is code-owned** — all sentences except greeting, sign-off, and the persona's configured signature and disclaimers. The model does not classify its own sentences.
- [ ] A citation counts only if its `chunk_id` was in this run's retrieved set and still resolves. **A hallucinated citation lowers the score.**
- [ ] Zero denominator → `NULL`. `NULL` never auto-sends.
- [ ] `model_confidence` stores the self-report. **Nothing reads it for a gate** — it exists so the gap can be watched.

### Task 3 — Citations (AC2)

- [ ] chunk id + source id + source title + excerpt at draft time.
- [ ] Excerpt denormalised deliberately — evidence, not a view.

### Task 4 — Persona (AC4)

- [ ] Tone, formality, signature, disclaimers into the system prompt.
- [ ] **Prohibited topics checked after generation**, not only stated before it.

### Task 5 — Timing (AC5)

- [ ] p95 from `received_at` to draft persisted.

### Task 6 — Failure surface (NFR23)

- [ ] A failed draft writes a `conversation_events` row (`draft_failed`) with one plain sentence. NFR23 names this exact case.
