## Story

**As a developer,**
**I want one mailbox model and a uniform connector interface,**
**so that the rest of the system never branches on provider.**

## Acceptance criteria

1. `mailboxes` table and RLS policy exist per the architecture.
2. A `MailboxConnector` interface defines `connect`, `refresh`, `fetchSince`, `send`, and `revoke`.
3. Credentials are encrypted with AES-256-GCM before storage; the key comes from `ENCRYPTION_KEY` and is never persisted in the database.
4. Credentials never appear in logs, error messages, or API responses.
5. Connection health (`sync_state`, `last_synced_at`, last error) is readable per mailbox.

---

## Prerequisites

| Needed | For | Why |
|---|---|---|
| **`ENCRYPTION_KEY` generated and set** in all three environments | AC3 | A 32-byte key someone must generate and store as a Vercel environment variable. **Losing it makes every stored credential unrecoverable** — it is the one secret on this project with no reset path |

*Note the asymmetry with every other secret here: a Clerk or Resend key can be rotated from a dashboard. This one decrypts data at rest, so rotation means re-encrypting every mailbox row. Story 2.1 should decide whether that path exists now or is accepted as post-MVP.*

## Tasks

### Task 1 — The table (AC1, AC5)

- [ ] `mailboxes` in the Drizzle schema, per the DDL below. RLS policy DDL goes in `packages/db/migrations/policies/` per the pattern Story 1.3 establishes — **a table Drizzle creates arrives with no policy**.
- [ ] `sync_state`, `last_synced_at`, and a last-error field are readable per mailbox (AC5). These are what Story 2.2 AC5 and Story 1.7's `mailbox_broken` email read.
- [ ] Let Story 1.3's coverage test catch a missing policy rather than pre-empting it. That is the net working.

### Task 2 — `MailboxConnector` (AC2)

- [ ] The interface exactly as §4.1 specifies: `connect(tenantId, provider, code)`, `refresh(mailboxId)`, `fetchSince(mailboxId, cursor)`, `send(mailboxId, outboundId)`, `revoke(mailboxId)`.
- [ ] **Nothing outside `packages/email` may branch on provider.** That is the point of the interface, and Story 2.3 AC4 tests it with a shared conformance suite — write that suite here, with no implementations yet, so 2.2 and 2.3 are written against a test that already exists.
- [ ] **Define `RawMessage` here.** `fetchSince` returns them and §4.2 says both entry points normalise to one — but four stories referred to the type and none defined it (boundary audit SB-4). It must carry a **`provider_message_id` derived identically by every entry point**, because Story 2.7's dedup constraint is built on it: derive it differently in the webhook and the poller and the constraint never fires.
- [ ] The cursor is opaque `text`. Gmail uses a history id, Graph a delta token, IMAP a UID — **the caller must never interpret it**.

### Task 3 — Credential encryption (AC3, AC4)

- [ ] AES-256-GCM, key from `ENCRYPTION_KEY`, ciphertext into `credentials_encrypted bytea`. §13.1 and NFR11.
- [ ] **The key is never persisted in the database** (AC3) — it lives only in the environment, read through `server/env.ts` (§15.6).
- [ ] AC4 is a *negative* requirement and needs a negative test: credentials must not appear in logs, error messages, or API responses. **Assert it** — a test that triggers a connector failure and greps the captured log and the serialised error for the plaintext. A rule nobody has watched fail is indistinguishable from one that does not work.
- [ ] Redaction belongs in the error taxonomy (§15.9), not at each call site, or the one path that forgets is the one that leaks.

## Dev notes

### The table — [§6.2](../architecture/database-schema.md)

```sql
CREATE TABLE mailboxes (
  id                    uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id             uuid NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
  provider              text NOT NULL,     -- gmail | outlook | imap | inbound_webhook
  address               citext NOT NULL,
  display_name          text,
  credentials_encrypted bytea NOT NULL,
  sync_cursor           text,              -- opaque; never interpreted by the caller
  sync_state            text NOT NULL DEFAULT 'idle',
  last_synced_at        timestamptz,
  is_active             boolean NOT NULL DEFAULT true,
  created_at            timestamptz NOT NULL DEFAULT now(),
  UNIQUE (tenant_id, address)
);

CREATE INDEX idx_mailboxes_tenant ON mailboxes (tenant_id) WHERE is_active;
```

The partial index matters: polling reads active mailboxes on every cron tick, and inactive ones accumulate.

> **`connected_at` is needed and is not in §6.2.** Story 2.8's backfill has to know when the mailbox was connected in order to bound its range — see that story's boundary problem. Either add the column here or rely on `created_at`; **decide it in this story**, because 2.8 depends on the answer.

### `MailboxConnector` — [§4.1](../architecture/components.md)

> Owns OAuth with Gmail / Microsoft Graph and IMAP credentials. Stores refresh tokens encrypted, refreshes on demand, exposes a uniform `fetchSince(cursor)` / `send(message)` interface **so the rest of the system never branches on provider**.

### Standards

- **§15.6** — `ENCRYPTION_KEY` is read in `server/env.ts` and nowhere else.
- **§15.9** — connector failures throw taxonomy classes. Redaction lives there.
- **§15.1** — repositories take a `tx` from `withTenant()`.
